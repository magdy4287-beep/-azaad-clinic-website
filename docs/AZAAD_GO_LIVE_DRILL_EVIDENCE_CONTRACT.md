# AZAAD Go-Live Drill Evidence Contract

Status: **CONTRACT DEFINED — EXECUTION NOT PROVEN**

## Purpose

This document defines the evidence contract for the final AZAAD Go-Live Drill. It does not claim that the drill has been executed, that staff have been trained, or that production is certified.

The drill must be executed against one exact release baseline and its evidence must remain attributable to that baseline.

## 1. Preconditions

Before execution, record:

- exact Git commit SHA
- exact Vercel production deployment
- Appwrite identity/authentication readiness
- Neon production readiness
- current backup/recovery evidence
- rollback decision owner
- authorized human participants
- test accounts/roles used for the drill

A missing precondition is **NOT PROVEN**, never an implied PASS.

## 2. Production workflow drill

### Reception

`Search/Register → Patient 360 → Schedule → Check-in → Payment → Receipt`

Record:

- actor/role
- timestamp
- exact environment/release baseline
- expected result
- observed result
- evidence reference

### Doctor

`Queue → Patient → Clinical Workspace → Assessment → Diagnosis/Plan → Complete Visit`

Verify patient scoping, doctor identity binding, authorization, auditability, and safe failure behavior.

### Management/Owner

`Dashboard → Financials → Refund Request → Doctor Approval → Management/Owner Approval → Execution → Audit`

Verify that neither the browser nor AI can bypass or impersonate either approval step.

### Administration

`Users → Roles → Permissions → Audit → Configuration`

Verify least privilege and attributable sensitive actions.

### Patient Dashboard

`Authenticated Patient → Dashboard → Appointments → patient-facing information → safe AI assistance/fallback → Logout`

Verify patient isolation, session behavior, AI fallback, and logout/session invalidation.

## 3. Negative safety drill

The drill must explicitly attempt and record rejection of:

- unauthorized patient access
- cross-patient clinical access
- unauthorized financial access
- refund execution without doctor approval
- refund execution without management/owner approval
- AI approval or privilege escalation
- duplicate payment/refund
- invalid appointment transition
- expired/invalid session use
- unsafe state change after AI failure

Expected rejection must be evidenced, not inferred from source code.

## 4. Recovery / rollback drill

Where the release requires recovery evidence, execute and record a controlled recovery/rollback exercise using the canonical architecture:

`Appwrite + Neon + Vercel`

Supabase remains historical migration/DR evidence only and must not be treated as the production runtime.

A backup that has not been restored is not proven recovery capability.

If recovery cannot be proven on the free-only stack, record:

`NOT PROVEN ON FREE-ONLY STACK`

Do not convert a missing capability into a paid dependency merely to obtain a PASS.

## 5. Human operational readiness

The following require actual human execution and cannot be generated by CI:

- staff training completed
- reception workflow performed by the intended operator
- doctor workflow performed by the intended operator
- management/owner financial workflow performed by the intended operator
- administration workflow performed by the intended operator
- incident/rollback decision exercise completed
- Go-Live owner sign-off

A document, automated test, or AI statement is not evidence that a human activity occurred.

For every drill item record:

| Notes/remediation | When applicable |

## 7. Release decision

The Go-Live Drill may only be marked **PASS** when all applicable positive, negative, recovery, and human-readiness scenarios have evidence for the same release baseline.

Otherwise the status is:

`NOT PROVEN`

No historical CI run, preview deployment, source inspection, or automated contract may substitute for missing human or production evidence.

## 8. Canonical safety rules

- Missing evidence is **NOT PROVEN**, never an implied PASS.
- AI cannot approve, impersonate, bypass, or execute around the refund chain.
- CI must not mutate source or weaken assertions to manufacture evidence.
- Production source of truth is GitHub `main` after release governance approval.
- Production runtime is Vercel.
- Authentication is Appwrite.
- Application data is Neon Postgres.
- Supabase is historical migration/DR evidence only.
- AZAAD remains 100% free-only.
